# MASKING.md — KLAN

Схема маскування чутливих даних перед передачею
у зовнішні API. Застосовується тільки до зовнішніх
API — локальні моделі, що відповідають умовам
CONCEPT.md, отримують дані без маскування.

## Категорії

| Категорія | Плейсхолдер | Що входить |
|---|---|---|
| Персона | `[PERSON_xxxxxx]` | ПІБ оператора, родичів, третіх осіб |
| Документ | `[DOC_xxxxxx]` | номери паспортів, ІПН, посвідчень |
| Дата народження | `[DOB_xxxxxx]` | повна дата |
| Адреса | `[ADDR_xxxxxx]` | місце проживання, реєстрації |
| Телефон | `[PHONE_xxxxxx]` | мобільні, домашні, робочі |
| Email | `[EMAIL_xxxxxx]` | особисті адреси |
| Медичне | `[MED_xxxxxx]` | діагнози, ліки, лікарі, заклади |
| Фінансове | `[FIN_xxxxxx]` | номери карт, рахунків, IBAN |
| Родинний зв'язок | `[REL_xxxxxx]` | «мати», «дружина», якщо ідентифікує |

## Формат плейсхолдера

Хеш: перші 6 hex-символів від SHA-256 значення
у нижньому регістрі.

Приклад: `Іван Петренко` → `[PERSON_8a3f1c]`.

Одна й та сама особа в різних документах отримує
однаковий плейсхолдер. Це дозволяє крос-аналіз
без розкриття.

Хеш не є криптографічним захистом (6 символів
можна перебрати). Він — технічний ідентифікатор
для аналізу, не механізм безпеки.

## Процедура

1. Маскування виконується **перед** будь-якою
   передачею у зовнішній API. Ніколи — після.
2. Таблиця відповідності зберігається локально
   у `sensitive/masking-map.md` (поза git).
3. Формат таблиці:
   `placeholder | оригінал | категорія | дата додавання`.
4. Якщо значення вже є в таблиці — використовується
   той самий плейсхолдер.
5. Якщо нове — додається запис, генерується новий
   хеш.
6. Після маскування текст перевіряється: пошук
   оригінальних значень із таблиці в підготовленому
   тексті.

## Що не маскується

- Публічні факти (назви установ, міст, організацій).
- Загальні дати (рік, місяць без дня, якщо не ідентифікує).
- Загальновідомі посади.
- Терміни, скорочення, технічні позначення.

## Непрямі ідентифікатори

Комбінація даних (рідкісна професія + місто + дата),
яка разом ідентифікує людину, не маскується окремо.
На поточному етапі — фіксується як обмеження.

Автоматичне виявлення непрямих ідентифікаторів —
поза межами поточної схеми. Рішення — після першої
практики.

## Перевірка

Після маскування:

1. Grep по підготовленому тексту для кожного
   значення з таблиці — жодне не має залишитися.
2. Перевірка на «залишкові» форми: скорочення імен,
   ініціали, транслітерація.
3. Якщо знайдено — маскування повторюється.
4. Результат перевірки фіксується в чаті ведучого
   (не в документі).

## Хто маскує

Оператор або ведучий під контролем оператора.
Ведучий не маскує автономно — тільки за явним
запитом оператора на конкретний текст.
