# CONCEPT.md — Личный корпус (ЛЧ)

Рабочий документ. Не канон. Меняется по факту.

## Что это

Закрытый персональный корпус данных о себе (операторе)
и связанных контекстах: семья, документы, медицинская
история, окружение и иные сведения, до которых можно
дотянуться.

Назначение:

- структурированное хранение и накопление;
- интерактивный запрос через LLM-агентов;
- кросс-анализ при сохранении периметра приватности.

## Что это не

- Не продукт.
- Не система слежки за третьими лицами.
- Не претендует на полноту. Отсутствие данных = UNKNOWN.

## Принципы

1. N=1. Только данные оператора и те данные третьих лиц,
   на которые есть законный доступ и согласие.
2. Документация определяет систему, а не описывает её.
3. Архитектура и ДДА адаптируются по ходу работы.
   Ничего не проектируется заранее сверх минимума.
4. Разделение статусов знания:
   FACT / INFERENCE / HYPOTHESIS / UNKNOWN.
5. Append-only с процедурой редикции.
6. Оператор — полноценный узел. Его решения логируются.
   Переопределение ранее зафиксированного FACT помечается
   OPERATOR_OVERRIDE.
7. Приватность — техническое ограничение, не декларация.

## Периметр приватности и кросс-анализ

Кросс-анализ допускается в одном из двух режимов:

- Локальные модели (Ollama, llama.cpp и аналоги) —
  полный доступ к корпусу.
- Внешние API (Claude, GPT, Gemini и др.) — только после
  явного решения оператора и при условии предварительного
  маскирования чувствительных материалов
  (PII, medical, family identifiers).

Передача полного контекста корпуса во внешние API
без маскирования запрещена.

## Уровни доказовости

- E0 — предположение / поисковый результат.
- E1 — URL / страница (доступна, но не загружена).
- E2 — загруженный файл.
- E3 — текстовый слой документа.
- E4 — визуально проверенный скан / OCR
  с подтверждением оператора.
- E4′ — корреляция с независимым артефактом
  (фото, документ, запись, стороннее свидетельство).
  Практический максимум для большинства субъективных
  данных N=1.
- E5 — независимое подтверждение вторым источником.
  Используется только при реальном наличии.

## Процедура редикции

1. Создаётся запись в REDACTIONS.md:
   «Данные [идентификатор] удалены / изменены по решению
   оператора от [дата]. Причина: …».
2. Исходный материал перемещается в карантин
   (`sensitive/quarantine/`, вне git) либо уничтожается.
   Выбор фиксируется в записи.
3. В месте удаления остаётся только ссылка
   на запись в REDACTIONS.md.

Карантин сохраняет данные локально вне репозитория.
Уничтожение означает полное удаление.

## Маскирование (базовый принцип)

Для внешних API чувствительные данные заменяются
на плейсхолдеры вида `[PERSON_xxx]`, `[PASSPORT_xxx]`,
`[MEDICAL_xxx]`.

Детальная схема маскирования фиксируется отдельным
решением при первой практической необходимости
(MASKING.md или раздел в CONCEPT.md).

## Угрозы (threat model)

- Утечка через внешние LLM-API при неосторожной
  передаче контекста.
- Компрометация git-истории.
- Ошибка оператора при внесении чужих персональных
  данных.
- Случайный коммит sensitive-файла до настройки
  .gitignore или до появления pre-commit проверки.

Меры: маскирование, каталог sensitive/ вне git,
обязательный .gitignore, `git add --dry-run` перед
добавлением файлов из raw/.

## Границы

- Не является продуктом.
- Не является системой слежки за третьими лицами.
- Не претендует на полноту. Отсутствие данных = UNKNOWN.

## Отношение к внешнему контуру

LAB (nova-cortex-lab) — внешняя основа метода.
Не источник контента, не часть ЛЧ. Изменения в LAB
не отражаются автоматически. Передача данных из ЛЧ
в LAB — только по явному решению оператора.

Envoy — параллельная пилотная ветка. Общий источник
(LAB), общий контур — разная природа данных. Обмен
между ЛЧ и Envoy не предполагается по умолчанию.

## Метод развития

Архитектура и онтология расширяются только после
появления практической потребности и фиксации решения
в DECISIONS.md.
