# CONCEPT.md — KLAN

Робочий документ. Не канон. Змінюється за фактом.

## Що це

Закритий персональний корпус даних про себе (оператора)
і пов'язаних контекстів: родина, документи, медична
історія, оточення та інші відомості, до яких можна
дістатися.

Призначення:

- структуроване зберігання і накопичення;
- інтерактивний запит через LLM-агентів;
- крос-аналіз із збереженням периметра приватності.

## Що це не

- Не продукт.
- Не система стеження за третіми особами.
- Не претендує на повноту. Відсутність даних = UNKNOWN.

## Принципи

1. N=1. Тільки дані оператора і ті дані третіх осіб,
   на які є законний доступ і згода.
2. Документація визначає систему, а не описує її.
3. Архітектура і ДДА адаптуються по ходу роботи.
   Нічого не проєктується заздалегідь понад мінімум.
4. Розділення статусів знання:
   FACT / INFERENCE / HYPOTHESIS / UNKNOWN.
5. Append-only з процедурою редагування.
6. Оператор — повноцінний вузол. Його рішення логуються.
   Перевизначення раніше зафіксованого FACT позначається
   OPERATOR_OVERRIDE.
7. Приватність — технічне обмеження, не декларація.

## Периметр приватності та крос-аналіз

Крос-аналіз допускається в одному з двох режимів:

- Локальні моделі (Ollama, llama.cpp та аналоги) —
  повний доступ до корпусу.
- Зовнішні API (Claude, GPT, Gemini та ін.) — тільки
  після явного рішення оператора і за умови попереднього
  маскування чутливих матеріалів
  (PII, medical, family identifiers).

Передача повного контексту корпусу у зовнішні API
без маскування заборонена.

## Рівні доказовості

- E0 — припущення / пошуковий результат.
- E1 — URL / сторінка (доступна, але не завантажена).
- E2 — завантажений файл.
- E3 — текстовий шар документа.
- E4 — візуально перевірений скан / OCR
  з підтвердженням оператора.
- E4′ — кореляція з незалежним артефактом
  (фото, документ, запис, стороннє свідчення).
  Практичний максимум для більшості суб'єктивних
  даних N=1.
- E5 — незалежне підтвердження другим джерелом.
  Використовується тільки за реальної наявності.

## Процедура редагування

1. Створюється запис у REDACTIONS.md:
   «Дані [ідентифікатор] видалено / змінено за рішенням
   оператора від [дата]. Причина: …».
2. Вихідний матеріал переміщується в карантин
   (`sensitive/quarantine/`, поза git) або знищується.
   Вибір фіксується в записі.
3. На місці видалення залишається тільки посилання
   на запис у REDACTIONS.md.

Карантин зберігає дані локально поза репозиторієм.
Знищення означає повне видалення.

## Маскування (базовий принцип)

Для зовнішніх API чутливі дані замінюються
на плейсхолдери виду `[PERSON_xxx]`, `[PASSPORT_xxx]`,
`[MEDICAL_xxx]`.

Детальна схема маскування фіксується окремим
рішенням за першої практичної необхідності
(MASKING.md або розділ у CONCEPT.md).

## Загрози (threat model)

- Витік через зовнішні LLM-API при необережній
  передачі контексту.
- Компрометація git-історії.
- Помилка оператора при внесенні чужих персональних
  даних.
- Випадковий коміт sensitive-файлу до налаштування
  .gitignore або до появи pre-commit перевірки.

Заходи: маскування, каталог sensitive/ поза git,
обов'язковий .gitignore, `git add --dry-run` перед
додаванням файлів з raw/.

## Відношення до зовнішнього контуру

LAB (nova-cortex-lab) — зовнішня основа методу.
Не джерело контенту, не частина KLAN. Зміни в LAB
не відображаються автоматично. Передача даних з KLAN
у LAB — тільки за явним рішенням оператора.

Envoy — паралельна пілотна гілка. Спільне джерело
(LAB), спільний контур — різна природа даних. Обмін
між KLAN і Envoy за замовчуванням не передбачається.

## Метод розвитку

Архітектура і онтологія розширюються тільки після
появи практичної потреби і фіксації рішення
в DECISIONS.md.
