## Q10.1 — Класи документів

Рішення: Варіант B — 7 класів + `other`.

Канонічний перелік (латиниця, lowercase):

    identity
    civil
    medical
    property
    financial
    legal
    correspondence
    other

Клас = ім'я каталогу в `sensitive/scans/<class>/`.

### Робочі правила класифікації

1. Один документ — один основний клас.
   Крос-категорійність — через теги, не через
   копії у кілька каталогів.
2. `other` — catch-all для документів, що не
   лягають у жоден із 7 класів. Періодичний
   перегляд `other` — окремою процедурою
   (TODO, після Q10.5).
3. Категорія чутливості — окремо від класу.
   Рівень маскування визначається MASKING.md,
   не цим файлом.
4. Перелік класів — append-only. Додавання
   нового класу — дозволено. Видалення чи
   перейменування — тільки рішенням GOVERNANCE
   з міграцією каталогу.

## Q10.2 — Канонічний формат

Рішення (2026-10-10):

1. Цільовий формат — PDF/A-2u; fallback — PDF/A-2b.
2. Конвертація не перекодовує растрове зображення.
   Скан вставляється в PDF як є (lossless-обгортка).
3. Оригінали JPG/PNG зберігаються без змін.
   Місце — визначається в Q10.4.
4. Конвертація виконується локально, без зовнішніх
   сервісів (периметр CONCEPT).
5. Якість і рівень PDF/A фіксуються в метаданих PDF
   (Producer), щоб пізніше можна було відрізнити,
   чим саме конвертовано.

Відкинуто: PDF/A-1b (надлишковий аскетизм),
PDF/A-3 (змішує ролі файлів). Перекодування
оригіналів — заборонено (втрата доказовості E4).

Перевірка після конвертації (обов'язкова):
- валідація PDF/A (інструмент — при першій практиці);
- фіксація результату в картці документа
  (`pdfa_status`: OK / FAIL / UNKNOWN).

Інструмент конвертації — узгоджується в Q10.3
(кандидат: ocrmypdf).

## Q10.3 — OCR-движок

Статус: WORKING BASELINE (2026-10-10).

Baseline: `ocrmypdf` + `Tesseract` (мови `ukr+eng`),
локально. ocrmypdf дає PDF/A-2u + OCR одним проходом,
не ламає конвеєр Q10.2.

Обґрунтування baseline: Apache 2.0, без телеметрії,
повністю локальний (периметр CONCEPT), працює без GPU,
природна інтеграція з PDF/A-2u.

Відомі обмеження Tesseract: рукопис, пошкоджені
скани, нестандартні шрифти, складний layout.

Відкладено: порівняння з EasyOCR / PaddleOCR —
окремий пункт roadmap після появи 3–5 реальних
зразків. Тоді ж — критерії (критичні поля, кирилиця,
час на сторінку).

## Q10.4 — Структура каталогів

Статус: WORKING BASELINE (2026-10-10).

    sensitive/scans/<class>/<ID>.pdf
    sensitive/scans/_originals/<class>/<ID>/page-NN.jpg
    sensitive/ocr/<class>/<ID>.txt
    sensitive/records/<class>/<ID>.md
    sensitive/tags/<ID>.yaml
    raw/masked/<ID>.md

### ID документа

Формат: `YYYYMMDD-<class>-<NNN>`

- `YYYYMMDD` — дата сканування;
- `<class>` — один із класів Q10.1;
- `<NNN>` — 3-значний лічильник у межах класу й дати.

Приклад: `20261010-identity-001`.

Один документ = один ID. ID не змінюється при
рескані — рескан створює новий ID із новою датою.

### Одиниця збереження

Одиниця — документ, не сторінка.

- Багатосторінковий документ — один ID.
- Сторінки зберігаються в каталозі
  `_originals/<class>/<ID>/` як `page-01.jpg`,
  `page-02.jpg`, …
- Порядок сторінок фіксується іменем файлу.

### Кроки конвеєра і статуси

1. Скан → `_originals/<class>/<ID>/`
2. Конвертація → `<ID>.pdf` у `scans/<class>/`
3. Перевірка PDF/A → `pdfa_status` у картці
4. OCR → `<ID>.txt` у `ocr/<class>/`
5. Перевірка OCR (критичні поля) → `ocr_status`
6. Картка → `records/<class>/<ID>.md`
7. Маскування (за потреби) → `raw/masked/<ID>.md`

`pdfa_status` і `ocr_status` — обов'язкові поля
картки. Значення: OK / FAIL / UNKNOWN.
Невдача кроку не блокує наступні, але маркує
документ. Приймання документа вимагає явних
статусів у картці.

### Теги

Теги (крос-категорійність) зберігаються окремо
від документа: `sensitive/tags/<ID>.yaml`. Формат
ключа — при першій практиці.

### Маскування

Маскування — явний крок 7. Виконується тільки
на запит оператора, не автоматично. Результат —
`sensitive/scans/` → `raw/masked/<ID>.md`.
Правила — MASKING.md.

Ревізія — при появі даних.
